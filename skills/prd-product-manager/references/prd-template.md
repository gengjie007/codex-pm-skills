# spec.html 章节与内容规范

模板沿用 SSL 规格经用户修订后的结构。七章顺序固定，章节内部按本次范围展开；无状态机或权限差异时写“不适用”及原因，不虚构内容。使用紧凑表格，不继承示例产品的功能数量、权限或配额。

## 封面与文档修订历史

- 产品名称、版本号、产品状态、文档评审状态、范围、日期。产品状态和文档评审状态分别表达；未知写待确认，不自行称“已上线/已评审”。
- 修订表：日期、版本、变更说明、负责人。负责人未提供时标待确认，不虚构姓名。
- 目录链接到各章及接口契约位置；可标功能/截图数量，但从实际内容统计。

## 一、需求信息（requirements）

- 模块概览表：序号、模块、类别（新增/bug修复/优化）、功能概述、需求方。
- **1.1 范围与目标**：用户问题、业务目标、适用对象、包含和不包含范围。没有证据的收益/指标写待确认。
- **1.2 主流程**：参与角色、前置条件、关键步骤、结果闭环。必要时说明跨模块依赖。
- 不自动加入来源文件绝对路径、文件哈希、工具说明或大段“本地原型”提示。

## 二、需求说明（functions）

按用户端/管理端或实际业务模块分组。每个功能使用 `<article class="feature" id="需求ID">`：

1. 功能名称、需求 ID、适用端/角色。
2. 入口与完整操作流程。
3. 对应实际截图（`figure > img`），图注含截图编号、功能名称；尺寸仅在真实读取后标注。多个关键状态可附多图，不重复无关图片。
4. 规格表：
   - **功能与规则 R-需求ID**：业务能力、前置条件、字段含义、默认值、必填/格式/长度、条件显隐、提交结果、依赖。按实际功能取舍，不能仅罗列控件。
   - **异常处理**：空/加载/失败、校验错误、权限变化、重复提交、并发冲突、部分失败、取消及恢复路径中相关的情形。
   - **验收 AC-需求ID**：明确输入/条件、操作、预期结果，包含关键正反例及边界。

### 接口与数据对象（contracts，属于第二章）

- 表：业务能力、输入与身份/范围、成功结果、错误语义、对应需求 ID。
- 记录对象关系、稳定 ID、归属、一致性、幂等/异步结果等适用要求。
- 已有 API 按证据引用；尚无接口的只提出建议契约，不虚构已实现 URL、协议细节或数据库方案。
- 不能把静态样例或按钮成功提示当作真实后端执行证据。

## 三、状态机说明（states）

- 对象、状态、含义、触发事件、转换条件、执行结果、允许操作。
- 覆盖成功/失败、中间态、终态与重试/取消（如适用）。
- 状态文案/颜色遵循用户或现有设计；状态定义、转换和功能规则一致。

## 四、交互与权限说明（permissions）

- 产品/资源权限分级、用户端角色矩阵、管理端矩阵（仅在实际存在时）。
- 矩阵写清角色、操作、数据范围、继承或覆盖关系。√允许、×不允许；未定义的符号保留未知含义，不自动转为允许/拒绝。用户明确解释后更新矩阵。
- 审批触发动作、审批角色、审批结果与业务动作的关系；未明确的会签/或签、自审等列入剩余事项。
- 通用交互：确认/关闭、回焦、无权限表现、身份与对象归属、凭据展示（按本次功能涉及程度）。
- 权限收紧要同步所有端、API及验收，不能在其他章节保留冲突的旧授权。

## 五、使用限制说明（limits）

表：限制项、明确规则/边界值、适用范围、确认状态。涉及容量、数量、长度、格式、日期范围、批量、去重/互斥等；没有业务证据的上限写待确认，不继承其他产品的20/50条等示例。

## 六、非功能性需求（nonfunctional）

按相关性列性能/容量、可靠性、鉴权与敏感数据、可用性/无障碍、审计、兼容性、缓存/发布一致性及测试要求。每项有可验证结果；未定 SLA 明示待确认，不编造指标。不自动继承某个项目“禁止流水线”等开发环境规则。

## 七、风险与边界说明（handoff）

- **7.1 确认结论与剩余事项**：稳定 D 编号、已确认结论/剩余问题、负责角色、阻塞范围、可先推进边界。已确认项不可继续列作未知；一条部分确认时拆清已定与未定部分。声明“不做A”不得泛化为“不做相邻能力B”。
- **7.2 原型与交付需求差距**：仅列影响研发的真实差距和需要实现的行为，不添加通篇原型免责声明。
- **7.3 plan.md 生成要求与建议工作包**：P编号、需求/AC映射、前置依赖、交付物、完成判据。覆盖前后端/数据/鉴权/异步/测试中实际适用部分；不以 UI 数量代替工作量。
- **7.4 验收覆盖与审核交接**：逐项功能、权限正反向、状态/并发、交互、兼容等实际必要维度，列验证证据。未审核不能称审核通过。
- **7.5 截图清单**：需求 ID、功能、截图编号。附件若需追溯以简短名称列出，不自动增加路径/哈希或长段采集说明。

## 最终一致性核对

名称/ID路由不串对象；规则与权限在各章节无冲突；附件业务约束已纳入；每功能有匹配截图及可验证AC；未确认项不伪装成确定要求；计划工作包可追溯至需求；数量、目录和图注与成品一致。

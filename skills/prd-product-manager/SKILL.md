# 产品需求规格 · Spec HTML

调用本技能默认意味着生成实际的 `spec.html` 文件，不以聊天正文或 Markdown 提纲代替交付。默认中文；用户指定文件名（例如 `ssl-spec.html`）、位置、语言或其他格式时遵循用户要求。修订既有规格时编辑原文件并保留此前确认的内容。

## 交付依据

先读 [章节与内容规范](references/prd-template.md)，使用 [HTML 模板](assets/spec-template.html) 的文档结构和视觉布局。模板源于已评审修订的 SSL 规格结构，但不携带 SSL 专属功能、权限、样例数据或截图。

- 成品为单个 UTF-8 HTML：内联 CSS/JS、目录锚点、打印样式、截图点击放大、窄屏可读。
- 所有内容图片使用完整的 `data:image/...;base64,...`；禁止本地路径、远程图片地址、截图占位符及外部字体依赖。成品可离线打开、复制和分享。复制到第三方编辑器后的图片保留取决于目标编辑器，不作未验证保证。
- 每个功能用稳定需求 ID 标识（如 `APP-U01`、`APP-A01`），配对应截图、规则及可验证的 `AC-需求ID`。编号随范围确定，不固定为 38 项或强制包含两端。
- 内容必须达到 Spec 级：业务行为、条件、结果、异常、状态、权限和验收可供研发拆解；不能只有 UI 外观描述。
- 用户明确确认的规则优先于旧附件和原型表现。区分已确认需求、原型已实现行为和实现建议；不得把建议当成既定需求，也不能让已确认事项继续显示为阻塞项。

## 两种输入方式

可混用两种方式，按用户实际材料选择。具体采集和配图规则见 [截图输入与核验](references/screenshot-inputs.md)。

### A. Agent 自行截图

用户给出原型 URL、HTML 或项目路径时，先读取必要代码和附件梳理功能，再用可用浏览器工具访问、操作并截图。读取该浏览器工具要求的技能说明；本地页面涉及图标、路由等资源时优先使用项目 HTTP 服务。按功能采集列表、详情、表单、确认窗口及关键异常状态。截图前检查当前路由、选中 Tab、弹窗和数据归属；查看实际图片后再嵌入。

### B. 用户粘贴或上传图片

用户在对话中粘贴截图、提供图片文件或截图目录时，直接以这些图片为依据，不要求重新截图。逐张关联功能、读取可见字段及用户说明；隐藏的交互、后端行为和权限不能由截图臆造。有关键图片缺失时先完成可确认部分，说明缺口并向用户索取相应材料。标注图可作为需求证据，但不得擅自重绘业务界面或抹去原始标注。

## 执行流程

1. **确认范围**：产品、用户端/管理端、版本、目标文件名与附件；能从材料确定的直接推进。读取用户提供的模板、权限表等附件，提取与本产品有关的要求，不照搬附件里的其他业务示例。
2. **建立映射**：按功能建立需求 ID → 截图 → 规则/权限 → 验收映射。需要时在交付目录保存截图及清单，HTML 本身不依赖目录。输入不足时保留明确缺口，不用其他功能的图片凑数。
3. **生成规格**：按模板七章顺序撰写，支持研发据此生成 `plan.md`。工作包映射需求 ID、前置依赖、交付物和验收；默认只提供计划拆解要求，不另行创建实现计划或修改应用。
4. **核对一致性**：同一规则在正文、权限矩阵、状态机、接口建议、验收和确认事项中一致；用户确认新规则后同步相关章节。已有技能/模板只指导结构，不覆盖用户的新结论。
5. **验证并交付**：运行下方校验，再浏览器检查桌面、窄屏、图片加载、目录和放大交互。逐张确认截图与功能匹配，列表图片不被无关弹窗遮挡。最终给出 HTML 的绝对路径链接，简要说明范围及尚存阻塞项；不自动提交、推送或发布。

```bash
python3 <本技能目录>/scripts/validate_spec.py /absolute/path/spec.html
```

校验脚本只检查结构、锚点、图片内嵌和验收标识，不能代替业务判断与视觉检查。若素材缺失导致无法满足每功能配图，交付时明确称为未完成草稿并列出缺口，不声称验证通过。可交付 HTML 的生成不应因非阻塞细项等待确认而全部停止。
